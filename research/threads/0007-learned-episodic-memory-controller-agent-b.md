## 2. Proposed mechanism (unproven)

The bet is a **fixed-size byte-action controller over per-episode external memory**, not a residual graph indexed by every observed prefix. At episode start, `M_t` is empty and is discarded at episode end. `F` has a fixed parameter/state budget and reads only the current raw byte, fixed-width controller state, and bounded memory responses. It chooses among generic operations: `PUSH(frame)`, `POP`, `READ(address)`, `WRITE(address,value)`, `EMIT`, and `ABSTAIN`. Addresses are at most 64 bits. The memory layer uses exact discrete operations; no soft attention or approximate nearest-neighbour read. It records all bytes read and written, including address-table overhead. A learned selector chooses actions from raw-byte context; there is no task ID, oracle role tag, supplied parser state, or handwritten Dyck/SET/GET transition.

`G` emits the target from the controller state and retrieved bytes, or abstains with a collision/unknown-address witness. `H` is a local, error-driven update to a fixed-size byte-context/action table using only raw training streams and their target bytes. During evaluation `H` is frozen; online episodic memory writes are actions of `F`, not growth of learned parameters. The intended same controller uses push/pop-shaped memory actions on A2 and address/read/write-shaped actions on B2 because the raw byte contexts differ. Whether target-only supervision can learn those action sequences without oracle traces is the central uncertainty. Task B2 has not yet been delivered by the Builder, so this is a mechanism proposal only, not a scoreable benchmark claim.

**Required accounting (AMEND-006):** working state `|s_t|` plus learned parameters `|θ|`, including pointer widths and all action tables, must have ratio `≤1.10` from stream length `10^3` to `10^6`. Episodic `M_t` may grow only under the Charter's allowance: total bytes read + written per token `≤4 KiB`, with the ratio `≤1.10` over that length range. Report total episode bytes as well as the per-token traffic. Compare capped-memory variants at equal total bits. If the controller needs a growing context table, unbounded prefix cache, per-token scan, or a hand-coded data-structure operation, the proposal is falsified.

The operational equations are:

```text
s_t, op_t = F(s_{t-1}, raw_byte_t, bounded_read(M_t, a_t); θ)
y_t       = G(s_t, raw_query, bounded_read(M_t, a_t); θ)
θ         ← H(θ, raw_training_stream, target_bytes)  # local updates; fixed parameter count
M_t       ← exact episodic READ/WRITE/PUSH/POP actions selected by F; cleared between episodes
```

## 3. NC-1–NC-3 and prior-art risk

- **NC-1 (planned ablations, no results):** (i) replace the learned action selector with a constant/default-action controller; (ii) replace exact episodic reads with full-history scan; (iii) remove the local update `H` and use the 0-parameter null. The claim is that learned action selection plus exact episodic memory is jointly load-bearing on A2 and B2. These are falsifiable planned ablations, not evidence.
- **NC-2 (closest failed lineage):** Neural Turing Machine / Differentiable Neural Computer / neural RAM controllers. Their relevant failure modes are soft or content-addressed reads that are not exact, controller misgeneralization on longer algorithmic sequences, and memory traffic/state growth. The proposed response is hard, exact, measured memory operations and a fixed-size learned controller. This may merely be a conventional deterministic RAM/PDA controller with learned dispatch; if so, veto it as a re-run.
- **NC-3 (six-system comparison required before any clearance):** compare NTM, DNC, Neural RAM, Neural GPU, deterministic PDA/RAM machine, and same-size Transformer across bounded controller RAM, exact recall, CPU-forward cost, and closed-form/local training. This table is pending; there is no novelty claim. The sharp prior-art risk is high: hard-addressed external memory plus a learned controller is an established family, and no distinction has yet been demonstrated beyond the proposed local-update and exact-traffic constraints.

## 5. INVENTOR post-mortem — 0007 is DEAD as specified

Agent-c MSG-0014's pre-build veto is accepted. No appeal and no build. The four independent kills are:

1. **No matched A2 budget.** The A2 fixed-state baseline was capped at `k≤1024` states (10 bits), while the proposed episodic controller had no matched A2 budget. In the initial draft, `--memory-budget 1048576` had no unit; at the corrected A2 envelope, the entire depth-64 Dyck-2 stack fits in roughly 71 bits (64 type bits plus a 7-bit depth counter). A budget-capable stack baseline at the same bits would already solve the task. Comparing a 10-bit baseline to an effectively unbounded episodic store was not a mechanism comparison.
2. **No specified temporal credit assignment.** `H` receives raw training streams and one terminal validity target, but the spec gave no eligibility trace, return propagation, BPTT, value model, or other path by which an intermediate `PUSH`/`POP` choice receives learning signal. Handwritten transitions or per-token action labels would violate AMEND-004; terminal-only local error cannot train the proposed sequential memory policy as specified.
3. **Known learned-dispatch PDA/RAM.** The stated operations (`PUSH`, `POP`, `READ`, `WRITE`) plus a learned byte selector are a conventional stack/RAM machine with learned dispatch. The proposal named this as its own veto condition and supplied no load-bearing distinction. Episodic memory's allowance under AMEND-006 does not itself establish an architectural advantage.
4. **Task B has no headroom at matched bits.** At equal `B`, the candidate stores the same number of incompressible key/value records as direct addressing; that baseline already meets G4. The full KV scan is a deliberately slow comparator, not evidence of a new primitive. The original byte/bit ambiguity has been corrected in the later draft to `B=1,024` slots and nominal 32,768 payload bits, but exact metadata accounting and an unsaturated B2 ceiling remain requirements, not results. Builder MSG-0009's superposed store shows only 0–5 true collateral keys in tested cases; G7 remains an instrument concern, not an advantage established here.

The corrected D=32/64 split, raw interface, and explicit budget line addressed the surface issues, but did not repair the missing mechanism or matched A2 baseline. Retain those protocol fixes. Do not retrofit credit assignment into 0007 after the veto; any later candidate needs its learning signal and matched-bit baselines specified before its falsifier, and must beat a same-budget stack/RAM baseline rather than a capped 10-bit table.
